# Веха исследования и руководство по продолжению

Статус: остановлено на офлайн-вехе 2026-10-27. Стенд для этого исследования не собирался,
адаптер не открывался, рабочий CAN-транспорт не добавлен. Продолжается сопровождение
K-line-приложения; дальнейшее дизассемблирование не требуется для выпуска этой работы.

## Что готово, а что нет

Рабочий продукт — K-line ROM-BSL читатель/писатель для измеренного эталонного ЭБУ.
Текущие исходники содержат рабочую панель операций и отдельный журнал; опубликованная
версия остаётся 1.0.1, её скриншоты предшествуют этому интерфейсу. Изменения исходников
не обновляют скачанные сборки релиза. Утверждённая иконка Chip 74 генерируется через
`tools/make_icon.py`. Новый релиз или расширение аппаратной поддержки этим не заявляются.

По резидентному CAN-загрузчику, ограниченному диапазону команд и нескольким путям
приложения/хранения есть офлайн-свидетельства. Стартовый обмен и согласование сессии
различаются. Восстановление байтов через короткие CRC работает в численных/p-code моделях;
реальный обмен с ЭБУ и полный бэкап из этого не следуют. Конечная модель клиента ограничена
127 четырёхбайтовыми областями (508 байт). Сброс приложения не является доказанной командой
входа. Инициализация хранения в режиме чтения может записывать последовательную память
в модели; это не безопасная проба без записи.

как независимые аппаратные проверки. Заголовок каждого инструмента и границы отчёта
называют подстановки, допущения и точки остановки. Хеш отчёта идентифицирует исполненный
код, а не подтверждает правильность этого кода или декодера C166.

## Воспроизведение без оборудования

Следующие команды не требуют прошивки или Ghidra и не открывают устройство:

```
uv run python tools/check_research_evidence.py
uv run python tools/check_can_crc_hypothesis.py
uv run python tools/check_can_reply_matching.py
uv run python tools/check_can_fifo_barrier.py
uv run python tools/check_docs_parity.py
```

Проверка свидетельств сверяет все 18 сохранённых JSON-отчётов с наследованием скриптов и
ссылками на опись. Она не исполняет прошивку повторно. CRC-команда без аргументов образов
проверяет только математику и явно сообщает об отсутствии проверки конкретной прошивки.
Эти проверки выполняются в CI вместе с проверками рабочего движка.

Исполнение прошивки дополнительно требует локального законно полученного образа,
Ghidra и совместимого модуля C166. Сохранённые прогоны загрузчика использовали Ghidra
12.1.4 и `C166:LE:16:default` со спецификацией компилятора `tasking`. Хеши декодера
записаны там, где доступны; сравнивайте их перед трактовкой изменившегося результата.
Не следует молча менять установленный декодер ради успешной проверки.

Для проверок приложения/хранения исследованный заводской образ — I444GI04, 851968 байт,
SHA256 `166bbdd475930e5fc2f15035435505fc999e07d8a2d915595246f45fe0bff59b`.
Он отличается от исторического стендового эталона в AGENTS.md. Проверка загрузчика также
принимает исследованные варианты загрузочных областей; точные хеши полных образов есть
в её отчёте. Образы храните вне репозитория. Команды используют условный путь, а не
включённый в поставку файл:

```
uv run python tools/check_can_loader_emulation.py PATH/TO/I444GI04.bin
uv run python tools/check_redundant_descriptor.py PATH/TO/I444GI04.bin
```

Аргументы входов и необязательного пути отчёта смотрите через `--help` каждого инструмента.
Временные импорты доступны только для чтения и удаляются. Обёртки проверяют конечный маркер
и хеш загруженного образа: Ghidra может успешно завершить процесс после ошибки скрипта.
Не обновляйте сохранённые хеши вручную после изменения скрипта: повторите соответствующую
проверку и исследуйте новые границы/результат. Поддерживаемые эксперименты не зависят от
частного архива чата или временного листинга.

## Продолжение от этой границы

Следующий решающий шаг — стендовые свидетельства точного ЭБУ/адаптера, начиная с
идентификации, проверки разводки/частоты и пассивного наблюдения по CAN_BENCH_PLAN.md.
Аппаратные операции требуют нового явного запроса, охватывающего их. Не следует начинать
со стирания/записи или выводить разрешение из существования плана.

Если пользователь сначала возобновит офлайн-разбор, остаются зависимая от данных обработка
полей в `0xC13FFC`/`0xC13794`, поздние записи запуска/выбора, полный диагностический
допуск и точный контракт очередей/свежести адаптера. У текущего обзора декодера есть
неразрешённая граница `0xC13FFE`; нельзя считать пропущенную семантику пустой операцией.
Эти пробелы не мешают сопровождению K-line-продукта. Не расширяйте поддержку ЭБУ и не
обещайте CAN-чтение/запись без пайки до прохождения соответствующих аппаратных этапов.
