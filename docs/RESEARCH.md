# Research checkpoint and restart guide

Status: paused at the offline milestone on 2026-10-27. No bench was assembled for this
research, no adapter was opened, and no production CAN transport was added. Continue
maintaining the K-line application; further disassembly is not needed to ship that work.

## What is ready, and what is not

The working product is the K-line ROM-BSL reader/writer for the measured reference ECU.
The current source includes the operation workspace and separate journal; the published
version remains 1.0.1, and its screenshots predate that interface. Source changes do not
update downloaded release binaries. The approved Chip 74 icon is generated by
`tools/make_icon.py`. No new release or hardware-support expansion is implied here.

The resident CAN loader, its restricted command range and several application/storage
paths have offline evidence. Startup/session negotiation are distinct. Short-CRC byte
reconstruction works in numerical/p-code models; actual ECU exchange and full backup do
not follow from it. The finite client stays capped at 127 four-byte ranges (508 bytes).
Application reset is not a demonstrated entry command. Read-mode storage initialization
can write serial memory in the model; it is not a safe non-writing probe.

## Reproduce without hardware

The following need neither firmware nor Ghidra and never open a device:

```
uv run python tools/check_research_evidence.py
uv run python tools/check_can_crc_hypothesis.py
uv run python tools/check_can_reply_matching.py
uv run python tools/check_can_fifo_barrier.py
uv run python tools/check_docs_parity.py
```

The evidence checker verifies all 18 archived JSON reports against script ancestry and
corpus references. It does not rerun firmware. The CRC command without image arguments
checks mathematics only and explicitly reports the missing firmware-specific check.
These checks run in CI alongside the production engine checks.

Firmware execution additionally requires a locally supplied, lawfully obtained image,
Ghidra and a compatible C166 module. The archived loader runs used Ghidra 12.1.4 and
`C166:LE:16:default`, with the `tasking` compiler specification. Decoder fingerprints
are recorded where available; compare them before interpreting a changed result. Do not
silently patch an installed decoder to force a pass.

For application/storage wrappers the reviewed stock image is I444GI04, 851968 bytes,
SHA256 `166bbdd475930e5fc2f15035435505fc999e07d8a2d915595246f45fe0bff59b`.
It is distinct from the historical bench reference in AGENTS.md. The loader wrapper also
accepts its reviewed boot variants; its report records the exact full-image hashes.
Keep images outside the checkout. Example commands use a placeholder, not a bundled file:

```
uv run python tools/check_can_loader_emulation.py PATH/TO/I444GI04.bin
uv run python tools/check_redundant_descriptor.py PATH/TO/I444GI04.bin
```

Use each wrapper's `--help` for its input and optional report path. Scratch imports are
read-only and temporary. Wrappers check the final sentinel and loaded-image hash because
Ghidra can exit successfully after a script error. Do not update archived hashes by hand
after editing a script: rerun the relevant wrapper and review the new scope/result.
No maintained experiment depends on a private chat archive or a scratch listing.

## Resume from this boundary

The next decisive step is the exact ECU/adapter bench evidence, starting with identity,
wiring/clock verification and passive observation in CAN_BENCH_PLAN.md. Hardware operations
require a new explicit request covering them. Do not start with erase/program or infer
permission from the existence of this plan.

If the user resumes offline investigation first, remaining targets are data-dependent
field processing at `0xC13FFC`/`0xC13794`, later startup/selector writers, full diagnostic
admission, and an exact adapter queue/freshness contract. The current decoder survey has
an unresolved boundary at `0xC13FFE`; do not treat omitted semantics as a no-op. None of
these gaps prevents maintenance of the K-line product. Do not broaden ECU support or
promise solder-free CAN reading/writing until the corresponding hardware gates pass.
